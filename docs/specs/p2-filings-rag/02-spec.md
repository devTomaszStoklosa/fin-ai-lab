Status: Ready for architect
Owner role: BA
Upstream: 01-story.md

## Glossary

| Term | Meaning |
|---|---|
| Korpus | zbiór zaindeksowanych sprawozdań dla spółek z listy w `01-story.md` |
| Sprawozdanie | 10-K (US, SEC EDGAR) albo raport roczny (GPW, PDF z relacji inwestorskich) |
| Fragment (chunk) | fragment tekstu sprawozdania przygotowany do wyszukiwania i cytowania |
| Cytat | wskazanie źródła odpowiedzi: spółka, dokument, okres, sekcja, fragment tekstu |
| XBRL | ustrukturyzowane dane liczbowe towarzyszące 10-K (tag, wartość, okres, jednostka) |
| Tag XBRL | identyfikator pojęcia finansowego w XBRL (np. `Revenues`); to samo pojęcie bywa pod różnymi tagami między spółkami i latami |
| Odmowa | jawna informacja, że system nie znalazł odpowiedzi, zamiast zgadywania |
| Pytanie poza korpusem | pytanie o spółkę, rok albo fakt, którego zaindeksowane dokumenty nie zawierają |

## Actors and permissions

| Actor | Action | Allowed |
|---|---|---|
| Właściciel | zadaje pytanie o sprawozdanie, w PL albo EN | tak |
| Model (LLM) | generuje odpowiedź tekstową na podstawie zwróconych fragmentów | tak — tylko z cytatem, bez liczb z pamięci |
| Model (LLM) | liczy albo przelicza wartość finansową | nie — wartości liczbowe pochodzą z XBRL albo z cytowanego fragmentu, nigdy z generacji |
| Model (LLM) | rekomenduje kupno/sprzedaż/zmianę pozycji | nie — reguła repo (`CLAUDE.md` zasada 5, [ADR 0006](../../adr/0006-descriptive-reports-no-investment-advice.md)) obowiązuje też tu, nie tylko w P1 |
| Narzędzie wyszukiwania (retrieval) | zwraca fragmenty i ich metadane | tak — tylko odczyt zaindeksowanego korpusu |
| Narzędzie XBRL | zwraca wartość + okres + jednostka dla tagu i spółki | tak — tylko odczyt |

## Functional requirements (EARS)

Indeksowanie i korpus
- REQ-001 (AC-1, AC-6): The system shall index only the companies and filings listed in `01-story.md`'s resolved corpus (US: Microsoft, Amazon, Oracle, Citigroup, NextEra Energy — SEC 10-K + XBRL; GPW: Atrem, PKN Orlen, ING Bank Śląski — annual report PDF from investor relations).
- REQ-002: When a filing is indexed, the system shall split it into chunks carrying company, filing type, fiscal period, section, and source location sufficient to build a citation.
- REQ-003 (AC-7): Before any filing content is sent to the model, the system shall pass it inside a delimited data section with an instruction that the section contains data, not instructions, the same pattern as P1's REQ-007.
- REQ-004 (AC-7): If a chunk contains text that addresses the model or resembles instructions, then the system shall flag it and shall not let its content change retrieval or generation behavior.

Wyszukiwanie i odpowiedź opisowa
- REQ-010 (AC-1): When the user asks a descriptive question, the system shall retrieve the chunks most relevant to the question before generating an answer, and shall generate the answer only from the retrieved chunks plus the question.
- REQ-011 (AC-1, AC-5): The system shall answer in the language of the question regardless of the source document's language, and shall quote cited excerpts in their original language.
- REQ-012 (AC-4, AC-6): If no retrieved chunk is relevant enough to the question, or the question names a company outside the corpus, then the system shall say explicitly that it found no answer or has no data for that company, instead of generating a speculative answer.

Cytaty
- REQ-020 (AC-1, AC-2, AC-3): Every fact-bearing sentence in a generated answer shall carry a citation identifying the company, the filing, the fiscal period, the section, and an excerpt locating it in the source document.
- REQ-021 (AC-3): When the user asks a year-over-year (or period-over-period) comparison, the system shall present each period's figure with its own citation, not a single citation covering both.

Dane liczbowe (XBRL)
- REQ-030 (AC-2): When the user asks for a value that exists in the company's XBRL data, the system shall answer with that value, its fiscal period, and its unit, taken from XBRL, and never from text generated by the model.
- REQ-031: The system shall resolve a financial concept to a single reported value even when the concept's XBRL tag changed across filings (e.g. a revenue-concept tag change after ASC 606 in 2018), using a maintained tag-alias mapping.
- REQ-032: If the same fiscal period is reported in more than one filing, then the system shall use the observation from the most recently filed one.
- REQ-033: If a concept is reported in more than one unit for the same period, then the system shall filter to the unit the question implies (or the filing's primary reporting unit) rather than mixing units.

Bez rekomendacji
- REQ-040: The system shall not answer a question asking for a personalized investment recommendation (buy/sell/hold/increase/decrease); it shall explain that this is investment advice and out of scope, the same rule as P1's ADR 0006.

## Business rules

Decyzja: odpowiedź czy odmowa

| Najlepszy dopasowany fragment powyżej progu trafności | Spółka w korpusie | Wynik |
|---|---|---|
| tak | tak | generowana odpowiedź z cytatem(-ami) |
| nie | tak | odmowa: „nie znalazłem odpowiedzi w zaindeksowanych dokumentach” |
| – | nie | odmowa: „brak danych dla tej spółki w korpusie” (inny komunikat niż wyżej — rozróżnienie ważne dla AC-4 vs AC-6) |

Próg trafności (ASSUMPTION: wartość dobierana empirycznie na golden secie w P2-S2, nie z góry — patrz Open questions #2 w `01-story.md` dla analogicznej decyzji przy embeddingach).

|---|---|
| tak | obserwacja z najnowszą datą złożenia (`filed`) wygrywa |
| nie | jedyna dostępna obserwacja |

## Data and validation

Fragment (chunk) w schemacie kanonicznym

| Field | Type | Required | Range or format | Validation message |
|---|---|---|---|---|
| `company` | string | tak | jedna ze spółek z resolved corpus | `Unknown company '<value>'` |
| `filing_type` | enum | tak | `10-K` / `annual-report-pl` | `Invalid filing type '<value>'` |
| `fiscal_period` | string | tak | np. `FY2025`, `FY2024-Q4` | `Missing fiscal period` |
| `section` | string | tak | 1–200 znaków | `Missing section label` |
| `text` | string | tak | niepusty | `Empty chunk text` |
| `source_location` | string | tak | strona/akapit/URL wystarczający do odtworzenia cytatu | `Missing source location` |
| `language` | string | tak | ISO 639-1 (`en`/`pl`) | `Unknown language '<value>'` |

Cytat w odpowiedzi

| Field | Type | Required |
|---|---|---|
| `company` | string | tak |
| `filing_type` + `fiscal_period` | string | tak |
| `section` | string | tak |
| `excerpt` | string | tak — fragment źródłowy, w oryginalnym języku |

XBRL — obserwacja wartości

| Field | Type | Required |
|---|---|---|
| `concept` | string | tak — pojęcie po rozwiązaniu aliasów tagów |
| `value` | Decimal | tak |
| `unit` | string | tak |
| `fiscal_period` | string | tak |
| `filed` | date | tak — data złożenia zgłoszenia źródłowego |

## Edge and error cases

- Ten sam koncept finansowy pod różnymi tagami XBRL zależnie od spółki i roku (`Revenues`, `RevenueFromContractWithCustomerExcludingAssessedTax`, `SalesRevenueNet`) — patrz `docs/DATA-SOURCES.md`.
- Tabele w 10-K (HTML) i w raporcie PDF GPW — najtrudniejsza część parsowania (P2-S1).
- Pytanie w PL o dokument EN i odwrotnie — odpowiedź w języku pytania, cytat w oryginale (REQ-011).
- Pytanie o spółkę spoza korpusu — odmowa z innym komunikatem niż „nie znalazłem odpowiedzi” (REQ-012, tabela decyzji).
- Fragment sprawozdania zawierający tekst przypominający polecenie dla modelu (prompt injection) — maskowanie/flagowanie jak w P1 (REQ-003/004).
- Pytanie proszące o rekomendację inwestycyjną — odmowa z wyjaśnieniem (REQ-040).
- Wartość XBRL zaraportowana w kilku jednostkach dla tego samego okresu — filtrowanie po jednostce (REQ-033).
